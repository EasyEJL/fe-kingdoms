# Native protocol, mixed-army version 4

The host serializes decimal integers and parses numeric output. Fe owns their game meaning. At most 240 actions and 16,384 input bytes are accepted. Invalid input exits 2 without emitting partial successful state; output failure exits 3.

Input:

```text
4 MODE DIFFICULTY SCENARIO COUNT
KIND FROM TO AMOUNT
...COUNT records...
```

Modes: 0 replay then finish Red's turn; 1 replay only; 2 complete self-play; 3 choose/apply one Fe action for the current side. HTTP exposes only 0 and 1. Difficulty is 0 Easy or 1 Hard. Scenario is 0 small, 1 medium or 2 large. Tile indexes are q + width*r. Every action must exactly match one generated by Fe.

Kinds: 0 pass (remaining fields zero); 1 move; 2 recruit two; 3 fortify one; 4 build/upgrade settlement (amount is new level); 5 recruit cavalry; 6 recruit siege; 7 train one infantry into cavalry; 8 train one infantry into siege. Specialist orders use amount 1. For non-move territorial orders FROM equals TO.

Output tags:

- 0: version, difficulty, accepted trace length.
- 1: side, orders, side-turn number, result, Blue gold, Red gold, consecutive passes, last action's four fields, search nodes, configured depth.
- 2: tile index, owner, troops, fort, supplied, terrain, q, r, settlement level, passable, upkeep, infantry, cavalry, siege.
- 3: a legal action's four fields.
- 4: accepted action index and four fields.
- 5: legal-action index, outcome, gold cost, source troops after, target troops after, target owner after, next side, next orders, result, defense before, food cost, settlement after, Blue food after, Red food after, moving infantry/cavalry/siege, attack power, remaining source infantry/cavalry/siege, remaining target infantry/cavalry/siege. Non-moves emit zero moving composition and attack power.
- 6: width, height, count, topology, scenario, Blue capital, Red capital, order budget, maximum side turns.
- 7: side, food, gold income, food production, upkeep, production-minus-upkeep, disconnected tiles, projected shortage losses, projected food after next upkeep. Projection uses the same Fe turn transition with an unchanged board.

Results: 0 ongoing, 1 Blue victory, 2 Red victory, 3 draw. Owners: 0 neutral, 1 Blue, 2 Red. Terrain: 0 plain, 1 farm, 3 hill, 4 capital, 5 mountain, 7 pass. Settlement: 0 none, 1 village, 2 town. Outcomes: 0 end turn, 1 friendly move, 2 capture, 3 repelled, 4 recruit, 5 fortify, 6 settlement.

Version 1 uses the older header without scenario; versions 2 and 3 have the same header shape as v4 but different rules/output fields. The host routes these only to frozen read-only executables. Output schemas must be interpreted by their declared version, not silently reclassified.
